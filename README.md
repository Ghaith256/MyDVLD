# DVLD: Driving and Vehicle License Department

Welcome to my project! I am a third year Computer Science student, and this is my second major desktop application. DVLD is a full Windows Forms program that manages a driving license department. I built it using C# and .NET 8, and it uses SQL Server for the database. 

## What the Application Does

* Manage people (add, update, search, show details, delete).
* Manage system users with secure login and password change.
* Manage application types and their fees.
* Create local driving license applications for a person.
* Schedule vision, written, and street tests for an application.
* Record test results (Pass or Fail).
* Manage license classes and test types.

## Technologies Used

* C# and .NET 8
* Windows Forms for the user interface
* SQL Server for the database
* ADO.NET (`SqlConnection`, `SqlCommand`, `SqlDataReader`) to communicate with the database
* SunnyUI and FontAwesome.Sharp for modern controls and icons
* BCrypt.Net for hashing user passwords securely
* xUnit for unit testing

## Project Structure

The solution file is called `MyDVLD.sln`. It contains five projects, and each project has its own folder. I used a 4 Tier Architecture to keep the code clean, readable, and easy to maintain.

| Project | Purpose |
|---|---|
| `DVLD_DTOs` | Simple classes that carry data between the layers. |
| `DVLD_DataAccess` | Runs SQL queries and communicates with the database. |
| `DVLD_Business` | Holds business rules and the objects used by the forms. |
| `DVLD_Presentation` | Contains the Windows Forms screens and user controls. |
| `DVLD_Test` | Contains unit tests for the Business layer. |

### DVLD_DTOs
This project contains the Data Transfer Object (DTO) classes. A DTO is a simple class with properties and no business logic.
Examples include:
* `PersonDTO`
* `UserDTO`
* `ApplicationDTO`
* `LicenseClassDTO`
* `TestAppointmentDTO`
* `TestDTO`

### DVLD_DataAccess
This project contains the classes responsible for the database. Their names start with `cls` and end with `DataAccess`, for example:
* `clsPersonDataAccess`
* `clsUserDataAccess`

Each method in these classes opens a database connection, executes an SQL command, and returns the result. This is the only project allowed to write and execute SQL queries.
The class `clsDataAccessSettings` stores the connection string to the database. If your SQL Server name is different, you just change it there.

### DVLD_Business
This project contains the classes for the business logic. Their names start with `cls` and do not end with `DataAccess`, for example:
* `clsPersonBusiness`
* `clsApplicationBusiness`

Each class has a `Save()` method that decides whether to add a new record or update an existing one. The forms communicate with these classes and never call the DataAccess classes directly.

### DVLD_Presentation
This project contains the forms that the user interacts with. Forms are grouped by feature into folders:
* People
* Users
* Application Types
* Local Driving License Applications
* Tests
* Test Types
* Licenses
* Detained Licenses
* User Controls

Each form has two files:
* `.cs` (Contains the code I wrote)
* `.Designer.cs` (Contains the code generated by Visual Studio)

The class `clsGlobal` stores the currently logged in user in the property `CurrentUser`.
The startup project is `DVLD_Presentation`. The `Program.cs` file opens `frmLogin`, and after a successful login, it opens the main window containing buttons for the whole system.

### DVLD_Test
This project contains the unit tests. Each test class is named after the Business class it tests, for example:
* `clsPersonBusinessTests`
* `clsApplicationBusinessTests`
* `clsUserBusinessTests`

The tests create real records in the database and delete them safely when they finish.

## How the Four Tiers Work Together

The application is divided into four layers. Each layer has one specific job.

1. **Presentation:** The user interacts with the application by clicking buttons or entering information.
2. **Business:** Business rules are checked. For example, a person cannot have two active applications for the exact same license class.
3. **DataAccess:** SQL queries are executed against the database.
4. **Database:** SQL Server stores the data in tables.

The data flows like this:

Form (Presentation)
⬇
Business Class
⬇
DataAccess Class
⬇
SQL Server Database

DTO objects carry the data safely between all these layers!

## Database Setup

1. Open SQL Server Management Studio and connect to your local SQL Server.
2. Create a new database named `DVLD`.
3. Create the tables used by the project. The main tables are:
   * `People`
   * `Users`
   * `Countries`
   * `ApplicationTypes`
   * `Applications`
   * `LicenseClasses`
   * `LocalDrivingLicenseApplications`
   * `TestTypes`
   * `TestAppointments`
   * `Tests`
   * `Drivers`
   * `Licenses`
   * `InternationalLicenses`
   * `DetainedLicenses`
4. Make sure the column names match the names used in the SQL queries inside `DVLD_DataAccess`.
   For example:
   * The `Users` table uses the column `UserName`.
   * The `Password` column must be long enough to store a BCrypt hash, which takes about 60 characters.
5. Make sure the `Countries` table contains data, because the people forms load their country list directly from it.
